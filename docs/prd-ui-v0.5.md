# DevBot v0.5 PRD：移动端信息架构与交互

> 文档类型：产品需求文档（PRD）· 阶段门 2/5「产品规划」
> 上游：`docs/ui-redesign-requirements.md`（R1–R4，Lead）
> 下游：task-3 前端设计（`design/mobile-workbench.html`、`design/conversation-style.html`）→ task-4 实现 → task-5 测试
> 范围：DevBot 工作台（群聊 / 阶段门 / 任务 / 成员）的响应式信息架构 + 会话时间线视觉统一；只读，不含页面内发消息
> 结论：**PM approve（有条件）→ 进前端设计**，条件见 §14

## 1. 一句话

v0.5 让 DevBot 工作台在手机 375–430px 宽下**可用且像 DSH 主会话**：三断点重排（三栏 / 两栏 / 单栏+分段 tab），群聊时间线改为无气泡正文 + markdown、用户右侧胶囊、成员头合并、系统行紧凑，同时**不改 controller 语义、不加依赖、不改 DSH 源码、不造第二份群日志**。

## 2. 背景与问题（证据）

### 2.1 手机端被固定三栏挤坏

v0.4 工作台是三栏固定布局（`client.js` styles）：项目列表 196px + 时间线 `flex:1;min-width:0` + 信息区 252px。容器宽 375–430px 时 196+252+边框已超过容器宽，时间线被压到 ≈0 宽；底部状态文字（`client.js` 1083–1086 行）在窄宽下逐字竖排；右侧阶段门/任务/成员被裁切。用户实际场景是手机浏览器竖屏（375/390/430），当前不可用。

### 2.2 会话历史与 DSH 主会话不同族

当前时间线是「头像 + 气泡」体系（`styles.bubble`，用户气泡偏蓝、成员气泡带边框）。DSH 主会话是：assistant 无气泡直排 + markdown、用户右侧胶囊、工具行紧凑、排版克制。两者视觉语言不一致，用户要求统一。

### 2.3 不能回退的行为（v0.4 已修）

团队发现、按成员增量 retain/release、跨会话归并/去重、流式 settle 去重、上滑 `loadOlder`、贴底跟随（含「内容塌缩不误判贴底」）都是已验证语义。v0.5 只改布局与呈现，不得改变这些语义。

## 3. 用户与场景

- **主用户**：项目 owner（人类）。桌面为主、手机为辅；手机上只看不改。
- **S1 手机看进度**（375/390/430 竖屏，单手）：打开 DSH Web → DevBot 图标 → 默认进群聊 → 看最新几条 → 切「阶段门」确认当前阶段 → 切「任务」看有没有被 block → 返回会话。
- **S2 手机看历史**：上滑加载更早；到顶显示「已到最早」；切 tab 再回来滚动位置不丢。
- **S3 多项目**：点顶栏项目名 → 抽屉切换另一个团队 → 时间线只显示新团队消息。
- **S4 平板/窄桌面分栏**（560–899）：时间线 + 右侧信息区；项目列表收进顶栏下拉。
- **S5 桌面**（≥900）：保持三栏，用新时间线样式。
- **S6 弱网/重连**：会话列表暂时不可读时保留已有内容并提示重连，不误判为「没有项目」。

## 4. 目标与非目标

**目标**

- **G1 手机 375–430px 可用**：无横向滚动、无逐字竖排、无裁切；群聊区宽高 > 0，一屏可读。
- **G2 三断点 IA 清晰**：≥900 三栏；560–899 两栏 + 项目下拉；<560 单栏 + 顶栏 + 分段 tab。
- **G3 时间线视觉与 DSH 主会话同族**；markdown 子集安全渲染（转义优先）。
- **G4 行为不回退**：桌面三栏、贴底跟随、上滑加载、retain/release、归并与流式去重全部保持。

**非目标（v0.5 不做）**

- 页面内发消息、新建项目、未读 badge、点成员跳 DM（M2）。
- 下拉刷新、手势导航、PWA/离线、横屏专属布局（按宽度走同一断点）。
- 第二套主题/自定义配色、消息入场动画、骨架屏。
- 修改 DSH 主会话本身或 DSH 源码。

## 5. 信息架构

### 5.1 内容实体

| 实体 | 内容 | 角色 |
|---|---|---|
| 项目（团队） | 名称、人数、任务数、进行中、运行中、最近活动 | 全局上下文，决定看哪个团队 |
| 群聊时间线 | 人类消息、派单、成员互发、成员发言、系统条、日分隔、流式 | **默认视图，chat-first** |
| 阶段门 | 5 阶段：需求/规划/设计/实现/测试，完成数、当前阶段、门禁说明、阻塞数 | 进度视图 |
| 任务 | id、标题、状态、owner、阶段 | 执行视图 |
| 成员 | 名字、角色、phase、运行中、是否已打开历史、打开失败原因 | 团队视图 |

### 5.2 三断点与栏位

断点依据是**工作台容器可用宽度**，不是浏览器视口（DSH 侧栏展开、桌面窗口分栏会让容器窄于视口；手机浏览器两者一致）。

| 容器宽 | 布局 | 项目切换 | 信息区（阶段门/任务/成员） | 时间线 |
|---|---|---|---|---|
| ≥900 | 三栏：项目列表 196 / 时间线 flex / 信息区 252（保持 v0.4） | 左栏常驻列表，点击切换 | 右栏常驻，内部分段（保持 v0.4） | 中栏，新视觉 |
| 560–899 | 两栏：时间线 + 信息区 252 | 顶栏项目名 → 下拉/浮层 | 右栏常驻，内部分段 | 主栏 |
| <560 | 单栏：顶栏 + 分段 tab + 单视图 + 底部状态条 | 顶栏项目名 → 底部抽屉 | 提升为整页视图（tab） | 分段 tab 之一（默认） |

三栏示意：

```
┌──────────────────────────────────────────────────────────────┐
│ DevBot 工作台   商城重构 · 阶段 3/5                 ⟳  回到会话 │
├────────────┬──────────────────────────────┬──────────────────┤
│ 项目列表   │ 群聊时间线                    │ 阶段门/任务/成员 │
│ 196        │ flex（独立滚动）              │ 252（内部分段）  │
│ ● 商城重构 │ ...                          │ ①需求 ✓          │
│ ○ 登录优化 │ [上滑加载状态条]              │ ③设计 ▶          │
└────────────┴──────────────────────────────┴──────────────────┘
```

两栏示意：

```
┌──────────────────────────────────────────────┐
│ ←  商城重构 ▾                             ⟳  │
├──────────────────────────┬───────────────────┤
│ 群聊时间线（独立滚动）    │ 阶段门/任务/成员  │
│ ...                      │ （内部分段）      │
│ [上滑加载状态条]          │                   │
└──────────────────────────┴───────────────────┘
```

### 5.3 导航与状态保持

- 层级只有两层：**项目（全局）→ 视图（页内）**。不新增路由/页面层级，不改变侧栏 DevBot 入口与 main 面板 key。
- 「阶段门/任务/成员」的选中状态在移动分段 tab 与桌面右栏之间**共享同一状态**；群聊在桌面常驻、不占分段。
- 跨断点重排（旋转/缩放/侧栏开合）不丢：当前项目、当前视图、群聊滚动位置与贴底意图、各视图滚动位置。
- 返回只回 DSH 会话面板（现有行为），不拦截浏览器历史、不做手势 hack。

## 6. 移动端单栏 IA（<560）

```
┌─────────────────────────────────────┐
│ ←   商城重构 ▾                  ⟳  │ 顶栏 44–48（+ safe-area）
├─────────────────────────────────────┤
│  群聊    阶段门    任务    成员      │ 分段 tab（≥40，吸顶）
├─────────────────────────────────────┤
│ ─── 今天 ───                        │
│ 你                        〔胶囊〕   │ 群聊独立滚动（唯一滚动容器）
│ Lead  10:21                         │
│ 收到，我先拆 5 阶段，需求门…          │
│ 〔系统〕阶段 2 规划 → 已批准          │
│ ...                                 │
│ 上滑加载更早消息                     │ 底部状态条（单行 + safe-area）
└─────────────────────────────────────┘
```

### 6.1 顶栏

- 高度 44–48px（另加顶部 safe-area 内边距），固定不随内容滚动。
- 左：返回（←，≥40×40，aria-label「返回会话」）。
- 中：项目名（单行省略 + ▾，点击打开项目抽屉/浮层）。
- 右：刷新（⟳/「刷新」，≥40×40，aria-label「刷新」）。
- 顶栏不显示阶段数字、成员/任务计数（放到对应视图），保证单行不换行。

### 6.2 分段 tab

- 四项：**群聊（默认）/ 阶段门 / 任务 / 成员**；四等分；高度 ≥40；吸顶在顶栏下。
- 选中态：文字加粗 + 底部 2px 指示条 + 主文字色；未选中用次要文字色；不能只靠颜色区分。
- 点击即切换，无加载态（数据已在 controller 内存中）；不触发重新 retain/refresh/loadOlder。

### 6.3 群聊视图

- 唯一滚动容器；进入工作台默认显示群聊；默认贴底。
- 内容按 §11 时间线规则渲染；无输入框。
- 底部状态条常驻（见 6.5）。

### 6.4 阶段门 / 任务 / 成员视图

- **阶段门**：5 行纵向列表（序号+名称、完成数、门禁说明）；当前阶段 ▶ 高亮、已完成 ✓、未开始 ○；有阻塞时显示「N 个任务被阻塞」；整页可滚动。
- **任务**：每行「状态点 + id + 标题 + 状态 + owner + 阶段」；长标题最多两行省略；整页可滚动；空态「暂无任务」。
- **成员**：每行「状态点 + 名字 + phase + 运行中/未打开历史/打开失败原因」；整页可滚动；空态「暂无成员」。
- 三个视图各自记录滚动位置，切走再切回恢复。

### 6.5 底部状态条（仅群聊）

- 固定底部、单行、小字号、低对比；三态文案：
  - 加载中：「正在加载更早消息…」
  - 可加载：「上滑加载更早消息」
  - 到最早：「已到当前会话窗口最早处」
- 单行不换行（超出省略）；底部叠加 safe-area；最后一条消息不被状态条遮挡。

## 7. 两栏（560–899）与三栏（≥900）

- **560–899**：顶栏（同移动端，含项目下拉）+ 时间线（主，独立滚动 + 底部状态条）+ 信息区 252（内部分段 阶段门/任务/成员，保持 v0.4 交互）。项目列表不常驻。
- **≥900**：保持 v0.4 三栏与桌面信息密度：项目列表 196 / 时间线 flex / 信息区 252；顶栏保留标题、面包屑、刷新、回到会话；左栏点击切换项目。仅升级时间线视觉，不改栏宽与信息层级。
- 断点之间重排：平滑、不重载数据、不丢滚动与选中状态。

## 8. 项目切换

| 断点 | 入口 | 形态 |
|---|---|---|
| ≥900 | 左栏项目列表 | 常驻列表，当前项高亮 |
| 560–899 | 顶栏项目名 + ▾ | 顶栏下方浮层 |
| <560 | 顶栏项目名 + ▾ | 底部抽屉 |

- 列表项：项目名 + 「N 人 · N 任务 · N 进行中 · 运行中」；当前项高亮。
- 浮层/抽屉：标题「DevBot 项目」；最大高度不超过可视区 70%，内部滚动；点选后切换并关闭；点遮罩/关闭按钮/Esc 关闭且不切换。
- 空列表：「还没有带 Team 的会话」+ 一句引导（开 Team 会话，用 spawn_teammate 起 pm/designer/fullstack/tester）。
- 切换后：时间线回到新项目最新；当前视图保持不变；旧项目消息不残留（沿用现有 selectTeam 语义）。
- 不做搜索/置顶/重命名/删除/跨项目聚合；不新增 localStorage 记住项目（刷新后按现有逻辑选最近活动项目）。

## 9. 状态设计（空 / 加载 / 错误）

| 区域 | 状态 | 展示 | 行为 |
|---|---|---|---|
| 项目列表 | pending | 「加载中…」 | 不显示空态 |
| 项目列表 | ready 空 | 「还没有带 Team 的会话」+ 引导 | 不自动选项目 |
| 项目列表 | ready 有 | 列表 | 自动选最近活动项目（现有行为） |
| 项目列表 | 列表暂不可读（重连） | 保留现有列表 + 弱提示「正在重新连接…」 | 不误判为空、不清空 |
| 详情 | 无选中 | 群聊空态/自动选第一个 | 沿用现有行为 |
| 群聊 | 空 | 短引导（开 Team 会话起 4 角色 / 从会话 header 看阶段） | 不占满整屏，最多 3 行 |
| 群聊 | 加载更早中 | 状态条「正在加载更早消息…」 | 不重复触发 |
| 群聊 | 已到最早 | 状态条「已到当前会话窗口最早处」 | 不再触发 loadOlder |
| 群聊 | 加载更早失败 | 状态条回到「上滑加载更早消息」 | 保留已显示内容、不弹窗、不自动循环重试 |
| 成员 | 历史未打开/失败 | 成员行标注「未打开历史 / 打开失败：原因」 | 不阻塞群聊；重试由现有 controller 负责 |
| 团队 | 消失/被删 | 自动切最近活动项目 | 无项目则回空态 |
| 阶段门/任务/成员 | 空 | 各自空态文案 | 整页仍可操作 |

**全局**：任何错误都不用模态弹窗，不阻断返回/刷新/切 tab；错误文案用次要文字色，不使用大面积红色块。

## 10. 交互细节

- **触控目标**：<900 断点所有可点元素 ≥40×40（顶栏按钮、分段 tab、项目行、抽屉项）；视觉可小但热区补足；相邻目标间距 ≥8。≥900 保持 v0.4 桌面密度（鼠标场景，不强制 40）。
- **safe-area**：顶部/底部使用 `env(safe-area-inset-*)`，并保留现有 `--dsh-frame-top-clearance` 叠加；顶栏不被刘海遮挡，底部状态条不被手势条遮挡。
- **返回**：顶栏左键 = 现有「回到会话」；不做浏览器历史拦截。
- **刷新**：顶栏刷新 = 现有 refresh；刷新期间按钮禁用/显示进行中，内容不清空；完成后保持滚动位置（内容不足一屏时回贴底）。
- **上滑加载**：距顶部 <48px 触发一次（沿用现有阈值）；加载中不重复触发；到最早处不再触发；只在群聊视图生效。
- **贴底跟随**：贴底时新消息自动跟随；上滑离开底部后不自动拉回；切 tab/切项目/旋转/重排后语义保持；不把「内容塌缩夹紧 scrollTop」当作用户回到底部。
- **切 tab 保状态**：群聊记录 scrollTop + 贴底意图；切回时原本贴底→到最新，原本不贴底→保持原位置（不跳）；阶段门/任务/成员各自恢复滚动位置；切 tab 不出现「加载中」闪烁、不重新 retain、不触发 loadOlder。
- **切项目**：时间线回新项目最新；tab 不变；抽屉/浮层关闭；无旧项目消息残留。
- **滚动**：只有内容区滚动；顶栏/tab/状态条固定；**禁止横向滚动**；**禁止逐字竖排**（文本容器有最小可读宽度）；长代码块/长 URL 在消息内横向滚动，不撑破页面。
- **文本**：消息正文可选中复制；markdown 链接可点。
- **动效**：仅 tab 切换/抽屉开合用 150–200ms 透明度/位移；不做消息入场动画；不做花哨过渡。
- **键盘**：v0.5 无输入框，不涉及软键盘遮挡。

## 11. 时间线视觉与内容规则（只列约束，不做像素稿）

### 11.1 与 DSH 主会话同族

- **assistant**：无气泡、无头像框，正文直排；支持 markdown 子集：标题、段落、粗体/斜体、行内码、代码块、无序/有序列表、引用、链接；代码块不做语法高亮。
- **用户**：右侧胶囊（短消息单行胶囊、多行自然扩展），不显示头像/名字，时间弱化或省略；胶囊最大宽度不超过内容区 82%（对齐 DSH 用户消息栈）。
- **成员**：小头像 + 名字 + 时间一行；同一发送者连续消息**合并头部**（只在首条显示名字/时间；发送者变化、间隔 >5 分钟或跨日时重新显示），组内行距收紧。
- **派单/工具行**：单行紧凑（谁 → 谁 + 任务摘要 + 状态），视觉权重低于成员正文；不展示完整工具参数正文（正文以投递副本为准，避免双份）。
- **系统条**：居中、低对比、小字号、单行省略（可点击展开详情，由设计稿定）；门禁/任务事件带「阶段/任务」前缀；无气泡。
- **日分隔**：居中弱化「今天 / 昨天 / M月D日」；跨天必显示。
- **流式**：运行中文字用与 assistant 相同的直排样式追加，尾部「输入中」指示；settle 后替换为持久消息，不叠字、不闪空。
- **视觉层级**：成员正文 > 派单/工具行 > 系统条 > 日分隔（权重递减）。

### 11.2 排版与主题约束

- 只用 DSH 主题 token（`--dsw-alias-*`），深/浅色自动适配；禁止硬编码背景/正文颜色。角色色仅用于头像/身份点，浅色主题下必须可读（加边框/降饱和由设计定），不得扩散到正文与背景。
- 移动端正文 ≥13px，行高 ≥1.5；元信息 11–12px；消息内标题字号不超过页面标题层级，避免层级倒挂。
- 桌面正文最大阅读宽度对齐 DSH 主会话内容列（`clamp(680px, 会话列宽 × 0.64, 920px)`，不沿用 DevBot 旧的 760px 硬上限），移动端满宽减边距。
- 间距克制：消息组间距 > 组内行距；不使用大面积渐变、重阴影、多层圆角堆叠；不引入第二套图标体系（沿用现有内联 SVG/文字）。

### 11.3 允许与 DSH 主会话的差异（DevBot 特有）

- 成员身份（小头像 + 名字 + 角色色）——DSH 主会话没有，保留但弱化。
- 系统条（team/task 事件）、派单行、流式「输入中」指示——DevBot 特有，按 11.1 紧凑呈现。
- 除以上三点，正文排版、用户胶囊、间距、token 与 DSH 主会话一致。

## 12. 硬约束（不可越界）

1. **不改 controller 逻辑**：团队发现/选中、按成员增量 retain/release、`loadOlder`、贴底判定（含塌缩保护）、跨会话归并/去重、流式 settle、日分隔键值全部保持现有语义；响应式只改布局与呈现。
2. **不加依赖**：不引入 CSS 框架/组件库/图标库/markdown 库/状态库；markdown 子集自实现并转义（防 XSS）。
3. **不改 DSH 源码**：不新增 Host 路由、不改 session 事件、不加 forward event；只用现有 client 服务与 slot。
4. **不造第二份群日志**：群聊仍从 Lead/成员 Session 持久日志合并；不新增持久化。
5. 不改会话 header 的 DevBot 阶段按钮；侧栏 DevBot 入口与 main 面板 key 不变；版本只升 0.5.0。
6. 不新增页面内发消息、未读 badge、新建项目、成员跳 DM（M2 范围）。

## 15. 风险与开放问题

1. **断点按容器宽度**：DSH 侧栏展开时桌面视口 1280 的可用宽度可能 <900 而进两栏——需在真实 GUI 验证是否可接受；若不可接受，可改为「视口与容器双条件」（PRD 暂定容器优先）。
2. **560–899 两栏**：信息区 252 固定时，560 宽下时间线仅 ≈300px；若可读性差，设计稿可提「信息区可收起」，但偏离「两栏」结论需 PM/Lead 拍板。
3. **四段 tab 在 375 宽**：每段约 90px，「阶段门」3 字 + ≥13px 字号需验证不换行；必要时允许 tab 文案用 2 字（群聊/阶段门/任务/成员）。
4. **切 tab 保滚动**：单栏只显示一个视图，滚动容器可能被卸载；需在设计稿标注滚动容器归属（保挂载或记录位置），且不动 controller。
5. **markdown 子集自实现**：格式偏差与 XSS 是主要风险；底线是「转义优先 + 白名单」，Tester 必测 AC-15。
6. **角色头像色硬编码**：浅色主题下对比度不足风险；只允许在头像/身份点加边框或降饱和，不扩散成第二套配色。
7. **iOS 地址栏伸缩**：100vh 变化导致布局跳动；用容器高度/dvh 处理，验收以真机或 safe-area 模拟为准。
8. **长代码块/长 URL**：375 宽易横向溢出；必须在消息内横向滚动，页面级 `scrollWidth` 不得超（AC-01 覆盖）。
